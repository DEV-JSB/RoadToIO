# 개발 일지 작성

## 목적

작업자가 이 파일을 **노션에 그대로 복사해 붙여넣는다.** 따라서 형식이 곧
결과물이다. 노션이 못 읽는 문법(HTML 태그, 각주, 정의 목록)은 쓰지 않는다.

## 절차

### 1. 오늘 날짜 확인

추측하지 말고 반드시 셸에서 가져온다.

```bash
date +%Y-%m-%d
```

### 2. 오늘 파일 확인

`E:/Unreal/study-notes/projectf/devlog/<오늘날짜>-ProjectF.md` 가

- **없으면** → `E:/Unreal/study-notes/projectf/devlog/_TEMPLATE.md` 를 읽어 그 구조 그대로 새로 만든다.
  맨 위 제목의 `YYYY-MM-DD` 를 오늘 날짜로 바꾼다.
- **있으면** → 기존 내용을 읽고 **해당 섹션에 이어 쓴다.**
  덮어쓰지 않는다. 이미 적힌 항목을 지우지 않는다.

개념 하나를 길게 정리했다면(예: 내적, 판 공기저항) 별도 파일
study-notes의 `projectf/<주제>.md` (프로젝트와 상관없는 수학이면 `game-math/<주제>.md`) 로 빼고 일지에서는 상대 경로 링크만 건다.
작업자가 노션에서 하위 페이지로 넣는다.

### 3. 채우는 규칙

| 섹션 | 무엇을 |
|------|--------|
| **오늘 한 것** | 단계 번호(예: 3-4)와 함께. 모듈 이름·에셋 경로를 포함해 나중에 찾을 수 있게 |
| **최종 코드** | 오늘 바뀐 Custom HLSL 전체 + 핀 표. 핀은 `태그 이름 (자료형)`, Custom HLSL은 왼쪽(입력)/오른쪽(출력) |
| **티키타카** | **가장 중요.** 작업자가 실제로 한 질문을 `### Q.` 로, 답은 "왜"를 중심으로 짧게. 오해했던 것도 남긴다 |
| **습관 경보** | 이번 세션에서 낸 🚨 습관 경보와 실제로 걸린 함정·컴파일 에러(에러 문장 포함) |
| **결정한 것** | 판단과 그 이유 + 출처 표기. 규약을 새로 정했으면 `CLAUDE.md` 에도 반영 |
| **막힌 것 / 미해결** | 해결 못 했어도 반드시 적는다. 증상 + 시도한 것 |
| **다음에 할 것** | 다음 세션이 이걸 먼저 읽는다. 구체적인 동작으로 |
| **습관 체크** | 오늘 작업에 해당하는 항목만 체크. 해당 없으면 *해당 없음* |

### 4. 지킬 것

- **순수 마크다운만.** 제목/목록/표/체크박스/코드블록/인용까지만
- 링크는 study-notes 안 상대 경로 (`../paper-drag.md`, `../../game-math/vector-ops.md`)
- **한국어로 쓴다**
- 없는 내용을 지어내지 않는다. 안 한 일은 안 적는다
- RoadToIO 커밋 해시는 `git log` 로 확인해서 적는다 (게임 레포 커밋은 작업자가 한다)

### 5. 마무리

작성 후 study-notes에서 커밋·푸시까지 한다(이 레포는 Claude 담당. `timeout 90 git push`). 사용자에게는 **파일 경로 한 줄**만 알려준다. 전체 내용을 다시 출력하지 않는다.

## 인자 처리

- 인자가 **있으면** 그 내용을 중심으로 적되, 이번 세션에서 실제로 한 작업과 대조해
  빠진 것을 보충한다
- 인자가 **없으면** 이번 세션 전체를 돌아보고 위 섹션 규칙대로 정리한다
