확인 문제, 빈칸 채우기(①②③) 뼈대를 주지 않는다. 단계마다 **완성 코드 + 각 줄이 무엇을 하는지 짧은 설명**을 주고 사용자가 직접 입력·연결한다.
단계(예: 3단계 펄럭임)가 원하는 모습으로 동작하면 그때 **"구현에서 내적·외적을 어떻게 썼나" 회고 정리**를 함께 한다 (devlog 개념 노트로 남김).

**Why:** 2026-10-22 사용자가 퀴즈/빈칸에 지쳐서 "퀴즈내지말자.. 일단 구현을 하고 원하는 방향으로 나오면 … 정리하는 시간을 가지자"라고 제안함. 개념 선행 학습(외적 페이지)은 와닿지 않았고, 동작하는 결과를 보고 나서 역으로 이해하는 쪽을 원함.

**How to apply:** 2026-10-19의 "완성 코드 먼저 주지 말 것" 합의를 대체한다. 코드와 설명은 계속 명확히 분리하고, 값마다 "왜"는 한 줄 붙인다. 습관 경보·검증 절차는 유지. [[projectf-pareidolia-clone]] [[pin-type-not-color]]
